- **An image can set the user an exec without `user` runs as (#595).** The daemon reads
  `AGENTD_DEFAULT_USER` from the image's environment at startup: a user name, or digits read as
  a uid. A start request that omits `user`, from `exec` or `run --exec` alike, resolves it at
  each start exactly as it would resolve that string in `user`, so a user an earlier exec created
  resolves on the next. A request's own `user` still runs as given, `root` and `0` included. If
  the guest's `/etc/passwd` lacks the value, each start without a `user` answers
  `400 unknown_user`, and the detail mentions the variable. With it unset, nothing changes.
  Workload hook handlers still run as root. The agent recipe's `chown` of `/workspace` and a
  sync's in-guest deletions now ask for uid 0 by number, so an image's default user can't make
  them fail.
